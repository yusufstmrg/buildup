2. Executive Assessment
preserve Current state:                            
a strong product concept and credible enterprise UI shell, but not yet a world-class production Business Transformation Intelligence platform.
preserve The largest gap is not visual design.     
It is the gap between the UI/product narrative and the underlying production-grade data, tenancy, authorization, decision governance, AI gateway, integrations, outcome measurement, observability, and commercial infrastructure.
The product currently behaves like a sophisticated prototype/business demo in important areas: authentication/session state is still handled in client context/localStorage; demo data is hard-coded; score logic contains randomness; decisions are local state; admin enforcement is incomplete; strategic AI endpoint is unauthenticated; and the data model is only three core tables.
Firebase is present and correctly positioned in the current stack, but the application still carries Supabase artifacts and a direct PostgreSQL dependency. The architecture needs one canonical production data/control plane.
The latest master-plan target should be implemented as a system: Business Genome -> Universal Data Fabric -> Intelligence -> Decision -> Transformation -> Outcome Ledger -> Knowledge Graph -> Benchmark -> Learning Loop.

8. Firebase / Google Production Architecture
preserve Recommended canonical stack:              
Firebase Authentication + Firestore for transactional application state where appropriate + Cloud Run/Cloud Functions for APIs/workers + Cloud Storage for documents + Pub/Sub/Eventarc for eventing + BigQuery for analytical workloads + Vertex AI/Gemini for governed AI + Secret Manager + Cloud Logging/Monitoring.
Use PostgreSQL only where relational/analytical integrity materially benefits from it; place it behind a well-defined domain service rather than letting frontend code depend on raw database assumptions.
Use signed upload/download URLs and tenant-bound object paths for documents.
Persist raw source evidence separately from canonical business records so every AI statement can trace to source evidence.
Make all integrations asynchronous and idempotent; every sync job receives a correlation ID and produces a lineage/provenance record.
9. Authentication, Session and Tenant Security
Landing page is public and never auto-promotes a visitor into a client workspace.
Sign-in uses Firebase Auth; onAuthStateChanged controls app state: loading -> unauthenticated -> authenticated -> authorization-resolved.
Session persistence is Firebase-managed; no client-auth object in localStorage is trusted as identity.
Logout revokes local client state, resets caches, cancels active subscriptions, clears sensitive workspace memory and returns to public landing.
Every protected route has a client guard AND server authorization. Client guard is UX; server guard is security.
Every tenant-scoped record must resolve organization_id from the authenticated membership, never accept arbitrary org_id from the client without authorization proof.
Admin is a system-level privilege, not a UI string. Enforce on server/API and record access in audit log.
Use least privilege, explicit permission matrices, resource-level ABAC for sensitive operations, and dual approval for material financial/risk actions.
10. Universal Data Fabric
preserve Required connector families:              
Google Workspace, accounting, ERP, CRM, HRIS, banking/fintech, POS, procurement, REST/GraphQL, webhooks, SFTP, SQL, CSV/XLSX/JSON/XML, PDF/DOCX/PPTX and scanned documents.
Every connector defines: auth method, scopes, source schema, target mapping, sync frequency, backfill policy, rate limits, retry strategy, data classification, tenant ownership and health status.
Data quality engine should detect missingness, duplicates, schema drift, temporal gaps, outliers, reconciliation mismatches and stale feeds.
No AI insight is marked validated unless evidence has source, timestamp, scope, transformation lineage and confidence.
11. Business Genome
The Genome is the living operational model of each business: people, money, processes, customers, suppliers, assets, systems, risks, goals, capabilities and dependencies.
Genome nodes are versioned. Changes produce events so the system knows what changed, when, why and which downstream insights become stale.
Genome is the context backbone for every AI agent, diagnostic, decision and transformation plan.
12. BuildUp Intelligence Engine
Deterministic metric layer first; AI reasons over verified metrics, not raw ungoverned numbers.
Anomaly and variance detection.
Root-cause graph linking symptoms -> evidence -> causes -> drivers -> interventions.
Scenario engine with explicit assumptions and sensitivity ranges.
Recommendation engine producing Decision Objects with evidence, expected impact, downside, confidence, owner and approval authority.
Counterfactual simulator to compare expected outcome with baseline and actual result.
Benchmark engine with cohort definitions, normalization, privacy thresholds and publication governance.
13. AI Gateway and Agent Workforce
preserve All AI calls MUST go through one gateway. 
No page or component should call a model directly.
Policy Gate -> Data classification -> Context builder -> Model routing -> Tool permissions -> Structured output schema -> Evidence/confidence validation -> Human approval (when required) -> Execution -> Outcome capture -> Audit.
Support model routing by task: low-cost fast models for extraction/classification, stronger reasoning models for strategic synthesis, embeddings/vector retrieval for knowledge access.
Every agent has objective, scope, tools, permissions, KPI, autonomy level, escalation threshold, cost budget and owner.
Autonomy levels: L0 observe, L1 recommend, L2 act with pre-approval, L3 act within tightly bounded policies.
Material finance, tax, legal, payment, HR, security and irreversible actions require approval gates and full audit evidence.
14. Business OS and Transformation
Transform recommendations into initiatives with explicit baseline, target, owner, budget, dependencies, milestones and value hypothesis.
Workflow orchestration must support retries, compensation steps, timeouts, escalation and human handoff.
Each initiative continuously compares plan vs actual and feeds outcomes back into Intelligence.
Expert escalation is a controlled professional intervention layer with scope, SLA, conflict checks, worklog and outcome capture; not an uncontrolled marketplace.
15. Outcome Ledger and Economic Proof
Every value claim needs baseline, measurement period, intervention, actual outcome and attribution logic.
Separate estimated value, realized value, avoided loss and cash realized.
Show confidence and evidence quality next to value figures.
Gain-share billing must reference verified outcome records and agreed attribution rules.
Do not present synthetic demo figures as live client economics.
16. Security, Privacy and Compliance by Design
Tenant isolation tests are mandatory for every API and collection.
Centralized secrets in Secret Manager; never embed server secrets in client bundles.
Audit all privileged reads and writes.
Encrypt data in transit and at rest; minimize sensitive fields and apply retention policies.
Customer data and cross-customer benchmark datasets must be logically separated and governed by contract/consent/anonymization rules.
Add export/delete workflows, incident response, access reviews and backup/restore verification.
Add security headers, CSP, rate limiting, input validation, schema validation and payload size limits.
17. Commercial and Growth Architecture
Free Health Check -> Business X-Ray / paid diagnostic -> recurring BuildUp Intelligence -> Transformation / retainer -> enterprise.
Entitlements are server-enforced, not visual only.
Meter AI/model cost, connector volume, storage, users, reports and execution volume.
Billing webhooks are idempotent and reconciled to subscription state.
Create CRM lead/opportunity lifecycle from anonymous Health Check to qualified account to customer to expansion.
18. UX/Product Enhancements Needed
Replace prototype-like pages with evidence-rich executive workflows.
Add a persistent AI command bar: ask, inspect, explain, compare, act, approve.
Every number has a source/definition tooltip and a drill-down path.
Every recommendation has an explainability panel: Why this? Based on what? What changes if assumptions change?
Add timeline and decision history to every major object.
Add empty/loading/error/offline states systematically.
Preserve current premium dark/light design but make information hierarchy more consistent across modules.
Make navigation reflect the master-plan journey: Understand -> Decide -> Transform -> Prove -> Learn.
19. QA and Launch Gates
The platform should not be declared production-ready until all of the following pass:
Auth: sign-up, sign-in, reset, verification, refresh, logout, multi-session and expired token behavior.
Tenant: cross-tenant read/write attack tests, membership changes, role changes, admin boundary tests.
Data: connector auth, retries, backfills, idempotency, schema drift, reconciliation and lineage.
AI: prompt injection, tool authorization, data leakage, hallucination controls, structured output validation, model fallback and cost limits.
Decision: approval matrix, dual control, materiality thresholds, audit trail and rollback/compensation.
Transformation: workflow execution, retry, escalation, timeout and failure recovery.
Outcome: baseline/target/actual/attribution correctness.
Billing: entitlement enforcement, webhook replay, cancellation, upgrade/downgrade and invoice reconciliation.
Reliability: SLOs, alerting, backup/restore, disaster recovery and synthetic monitoring.
UX: all routes, deep links, mobile/responsive states, dark/light, language switching, accessibility.
Security: dependency scanning, secret scanning, CSP, rate limiting, OWASP-style API tests, audit review.
Real-client pilot: at least one complete end-to-end journey using actual customer data under signed terms.
